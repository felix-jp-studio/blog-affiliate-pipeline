UX PDCA 自動化 — 設計書

blog-affiliate-pipeline / sim-hikari-guide.com / 承認日: 2026-08-11

1. 要件

GitHub Actions が Check → Plan → Act を自律的に回し、Cursor Agent が UI/UX 改善 PR を指示なしで継続する。

  • 頻度: 水曜 10:00 JST（Visitability 火・金と非競合）
  • Act: 70% Agent（Issue 起動）+ 30% スクリプト（Prettier 等）
  • マージ: Pass → squash merge（validate + playwright-visual 必須）
  • 禁止: 記事 md / KW seed / data 変更

2. アーキテクチャ

ux-pdca-orchestrator.yml (cron 水 01:00 UTC)
  ├─ Check: collect-ux-metrics.mjs
  ├─ Plan:  plan-ux-cycle.mjs → data/ux-cycle-brief.json
  └─ Act:
       script  → run-ux-fixes.mjs → PR
       agent   → create-ux-agent-issue.mjs → Issue → Agent → PR
                                              ↓
                              ux-pr-gatekeeper: Pass→merge / Fail→close

3. データ

ファイル 役割
config/ux-pdca-state.json Cycle 番号・metrics・paused
config/ux-backlog.json 10 件の UX タスク（article-ui-v2 由来）
data/ux-cycle-brief.json 1 Cycle の実行指示

4. Plan ロジック

Check Act
CWV 退行 cwv-regression-fix 優先
open UX PR あり skip
backlog priority 最高 該当タスク
3 回連続失敗 paused + Issue

5. PR Gatekeeper

判定 条件
Pass validate + playwright-visual + allowlist + diff ≤ 400 行
Fail 記事 md 変更 / diff 超過 / チェック失敗

ブランチ: feature/ux-pdca* / ラベル: ux-pdca-auto
