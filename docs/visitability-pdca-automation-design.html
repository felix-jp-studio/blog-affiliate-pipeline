1. 要件整理

ゴール: GitHub Actions が Check → Plan → Act を自律的に回し、Agent の「続けて」指示なしで Visitability Cycle（記事追加・hub mesh・index queue）を継続する。

フェーズ 内容 自動化後
Check 記事数・index queue 消化率・タイプ比率 collect-metrics.mjs
Plan 次 Cycle テンプレート・KW 選定 plan-cycle.mjs
Act generator → onboard → queue → mesh → PR run-cycle.mjs + gatekeeper

合意済みデフォルト

  • 実行頻度: 火・金 JST 09:00（週2 Cycle）
  • 実行方式: 80% スクリプト + 20% Issue エスカレーション
  • 公開経路: PDCA Cycle は PR 統一（scheduled-articles は日次1本のまま main 直 push）

制約

  • GSC 手動ログイン・OAuth は Agent 不可
  • secrets をリポジトリに含めない
  • 既存 CI ゲート（validate / playwright-visual）を通過必須

4. PR Gatekeeper（Pass → merge / Fail → close）

visitability-pr-gatekeeper.yml は CI / Pull Request ワークフロー完了後に起動し、Visitability 管理 PR を評価する。

判定 条件 動作
Pass validate +（site/** 変更時）playwright-visual squash merge + コメント
Fail 必須チェック失敗 / allowlist 外ファイル コメント付き close
Pending チェック未完了 何もしない（次 WF 完了を待つ）
Skip Visitability 管理外 PR 何もしない

対象 PR

  • ブランチ: feature/visitability-cycle*, feature/visitability-pdca*
  • ラベル: visitability-cycle-auto
  • タイトル: Visitability Cycle N

5. run-cycle.mjs — 9ステップ

  1. keywords.seed.csv に brief の keywordAppend を追記
  2. config/batch-cycle{N}-auto.json 作成
  3. generator --mode template --batch ...
  4. post-publish-article-onboard.mjs --slugs=...
  5. append-index-queue.mjs --slugs=...
  6. update-hub-mesh.mjs（trouble は trouble セクション）
  7. Prettier format
  8. npm run test:e2e:articles
  9. state 更新 + PR 作成（WF 側）

6. 懸念・エッジケース

懸念 対策
GSC secrets 未設定 index queue 消化率のみで Plan（GSC メトリクスは skipped）
generator slug 未マップ fallback KW + Issue エスカレーション
Linux vs macOS visual 差異 CI Update visual baselines workflow 使用
3回連続失敗 paused: true で orchestrator 停止
