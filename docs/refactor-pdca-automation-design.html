Refactor PDCA 自動化 — 設計書

リポジトリ: blog-affiliate-pipeline / 承認日: 2026-08-11 / レーン: scripts & packages

1. 要件整理

ゴール: GitHub Actions が Check → Plan → Act を自律的に回し、scripts/ と packages/ のリファクタ・保守タスクを継続的に消化する。記事本文・site UI には触れない。

フェーズ 内容 自動化後
Check Prettier 乖離・TODO 数・open PR・backlog 残数 collect-refactor-metrics.mjs
Plan 次タスク選定（script vs agent） plan-refactor.mjs
Act script: Prettier 修正 PR / agent: Issue 起票 run-deterministic-fixes.mjs または Agent Issue

合意済みデフォルト

  • 実行頻度: 月・木 JST 10:00（Visitability / UX と非競合）
  • 実行方式: 80% Agent（Issue） + 20% スクリプト（Prettier 等）
  • diff 上限: 300 行 / 15 ファイル
  • ラベル: refactor-pdca-auto / ブランチ: feature/refactor-pdca-*

触る / 触らない

許可 禁止
scripts/, packages/ site/src/content/articles/
config/refactor-* site/src/components/, site/src/styles/
refactor PDCA 自身の WF / docs data/keywords.seed.csv, data/gsc-index-queue.json

2. アーキテクチャ

refactor-pdca-orchestrator.yml (cron 月・木 JST 10:00)
  │
  ├─ Check: collect-refactor-metrics.mjs → config/refactor-pdca-state.json
  ├─ Plan:  plan-refactor.mjs           → data/refactor-cycle-brief.json
  └─ Act:
       ├─ execution=script → run-deterministic-fixes.mjs → PR
       └─ execution=agent  → create-refactor-agent-issue.mjs → Issue
                                              │
                                              ▼ (script PR のみ)
                            refactor-pr-gatekeeper.yml
                              Pass → squash merge + bump cycle
                              Fail → close PR
                              Pending → 待機

Plan 判定

条件 Act
open refactor PR あり skip
Prettier 乖離 > 0 root-prettier-scripts-drift (script)
backlog 優先度順 先頭 pending タスク (agent)
3 回連続失敗 paused: true

4. PR Gatekeeper

refactor-pr-gatekeeper.yml は CI 完了後に Refactor PR を評価する。 playwright-visual は不要、validate 必須。

判定 アクション
pass squash merge + bump-cycle-state.mjs
fail PR close + コメント
pending 待機
