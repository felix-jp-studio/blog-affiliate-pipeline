1. 要件整理

ゴール: ユーザーが ASP 管理画面から取得した trackingUrl / programId を Agent が検証・反映し、サイト全体で config/asp-urls.json を正本としたアフィリエイトリンク管理を実現する。

機能 内容 Phase 1
Intake ユーザー入力 → asp-urls.json 更新 MVP
Generator プレースホルダ保存（URL 焼き込み廃止） MVP
記事移行 112 本のハードコード URL → {AFFILIATE:*} Phase 2
ヘルスチェック 週次 trackingUrl 到達性検証 Phase 2
Agent サイクル plan-sync + PR 自動化 Phase 3

制約

  • A8 / バリューコマース / もしもへの Agent 自動ログイン不可
  • tracking URL の推測・生成禁止（ユーザー提供のみ）
  • registry 変更は PR 必須（収益直結）
  • secrets をリポジトリに含めない

Intake 入力 JSON

{
  "programId": "4B8097+XXXXXXXX+XXXX+XXXXXXX",
  "trackingUrl": "https://px.a8.net/svt/ejp?a8mat=...",

programKey は CLI 引数（例: npm run affiliate:intake -- uq-mobile）または JSON の programKey / id フィールドで指定。

4. CAN / CANNOT

CAN Agent / CI CANNOT ユーザー必須
共有された URL の registry 反映 PR A8 / VC / もしもへのログイン
ホストパターン・programId 形式の検証 管理画面からのリンク取得（初回）
新規記事へのプレースホルダ保存 tracking URL の推測・生成
記事プレースホルダ移行 PR（Phase 2） 新規 ASP 提携申請・審査
週次ヘルスチェック + Issue（Phase 2） ASP ToS 上禁止される自動スクレイピング

5. 懸念・エッジケース

懸念 対策
URL 発明リスク intake で hostPattern 検証。未検証 URL は拒否
二重解決 Generator はプレースホルダ保存、Site がビルド時解決
pending program（UQ mobile 等） status: pending + fallbackUrl 維持。承認後 intake
112 本ハードコード移行 Phase 2 でカテゴリ別 PR（visual regression 影響大）
programId 不一致（ahamo vs ahamo-hikari） registry note + intake 時 label 照合

7. Phase 1 運用手順

  1. ユーザーが A8 / VC 管理画面でログインし trackingUrl を取得
  2. npm run affiliate:intake:dry-run -- <programKey> で JSON 入力・検証
  3. npm run affiliate:intake -- <programKey> で registry 更新
  4. PR 作成 → レビュー → マージ → Vercel デプロイ
  5. 新規生成記事は {AFFILIATE:*} のまま保存、ビルド時に解決
# dry-run 例
cat <<'EOF' | npm run affiliate:intake:dry-run -- uq-mobile
{
  "programId": "4B8097+TESTID+UQMO+BILE01",
  "trackingUrl": "https://px.a8.net/svt/ejp?a8mat=4B8097+TESTID+UQMO+BILE01",
  "provider": "a8",
  "status": "active"
}
EOF

8. Phase 2 運用手順

  1. npm run affiliate:migrate:dry-run -- --category sim で置換対象を確認
  2. npm run affiliate:migrate -- --category sim で sim カテゴリを移行
  3. PR 作成 → CI（validate-articles 警告数減少）→ マージ
  4. 残カテゴリ（hikari / cost / trouble）は同コマンドで順次移行
  5. 週次: affiliate-link-health.yml が trackingUrl 到達性と lastVerified 鮮度を検査 
# migrate 例
npm run affiliate:migrate:dry-run -- --category sim
npm run affiliate:migrate -- --category sim

# health 例
npm run affiliate:health:dry-run
npm run affiliate:health
